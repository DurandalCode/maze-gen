# Maze Lab

Локальная лаборатория для генерации и исследования полноразмерных лабиринтов. React + TypeScript strict, Bun, Vite, Three.js и Tauri 2. Интерфейс на русском. Без аккаунтов, серверов и телеметрии.

## Быстрый запуск

Установите [Bun](https://bun.sh/docs/installation) 1.4.4 или новее. Для браузерной версии Rust не нужен:

```sh
bun install
bun run dev
```

Откройте http://127.0.0.1:1420. Для desktop-режима после установки системных зависимостей:

```sh
bun run tauri dev
```

Если Bun ещё не добавлен в PATH, в этой рабочей копии скачан локальный экземпляр (в Git не входит). PowerShell:

```powershell
$env:Path = "$PWD\.tools\bun-windows-x64;$env:Path"
bun run dev
```

## Системные зависимости desktop

Полный актуальный список: [Tauri 2 prerequisites](https://v2.tauri.app/start/prerequisites/).

**Windows 10/11 x64**

- Rust stable (MSVC toolchain, Rust ≥ 1.90) через [rustup](https://rustup.rs/).
- Visual Studio 2022 или новее / Build Tools с workload **Desktop development with C++** и Windows SDK.
- Microsoft Edge WebView2 Runtime. На Windows 11 обычно уже установлен.
- Bun в PATH. Node.js не обязателен: Vite и TypeScript запускаются через Bun.

**macOS**

- Xcode Command Line Tools: `xcode-select --install`.
- Rust stable через rustup, Bun в PATH.
- Сборку macOS выполняйте на macOS. Apple Silicon и Intel требуют соответствующего Rust target/toolchain; локальная сборка по умолчанию использует архитектуру хоста.

## Использование

В разделе «Ориентиры» настраиваются лес и солнце; оба можно перетаскивать за подписи/значки на карте. Лес размещается с любой стороны, с отступом и сдвигом вдоль границы. Для солнца выберите день августа и время МСК (UTC+3); направление и высота рассчитываются автоматически. По умолчанию используются 15 августа, 13:00 и координаты центра Москвы 55.7558° с. ш., 37.6173° в. д. Положение рассчитывается приближённо по [формулам NOAA](https://gml.noaa.gov/grad/solcalc/solareqns.PDF), без атмосферной рефракции. За горизонтом солнечный диск и прямой свет скрываются. Перетаскивание солнца подбирает ближайшее дневное время для выбранного направления; недоступные в августе направления привязываются к ближайшей точке дневной дуги. Карта, видимый диск, освещение и тени используют одни настройки; они сохраняются в JSON и при повторной генерации.

«Просвечивающая ткань» действует на стены и крышу. Вблизи сохраняются мелкие просветы; вдали стены просвечивают только при преобладании света с обратной от наблюдателя стороны. Крыша скрывает дальнее окружение и показывает мягкое пятно из мелких светящихся точек вокруг направления на источник. При освещении спереди или без прямого света эффект исчезает. Учитываются солнце, точечные источники и прожекторы, включая их дальность и конус света.

1. Выберите Recursive Backtracker (длинные пути) или Randomized Prim (частые короткие ответвления).
2. По умолчанию выбраны **5 × 5** отдельных квадратных модулей **2 × 2 м**, проходы между ними **2 м**, **0** дополнительных соединений и высота стен **2,5 м**. Задайте число столбцов/строк модулей (1–100), размер модуля и проход между ними (каждый 0,8–10 м), seed и число дополнительных соединений. Изменения применяются кнопкой «Сгенерировать». «Классическая сетка» сохраняет прежнюю конструкцию без промежутков.
3. Карта: колесо меняет масштаб около курсора, перетаскивание двигает план, кнопка ⌖ вписывает его в экран. Вход зелёный, выход оранжевый. Кратчайший путь включается переключателем.
   В разделе «Входы и выходы» можно добавить несколько проёмов на внешнем периметре: нажмите «Добавить вход-выход», затем на нужный участок границы карты. Кнопка ↗ перемещает проём, × удаляет (минимум два). Все проёмы соединены общей сетью. Выберите любые «Старт» и «Финиш»; «Поменять местами» разворачивает направление. Карта, метрики и прохождение используют выбранную пару. Список проёмов и направление сохраняются в JSON и сохраняются при повторной генерации; при изменении сетки позиции переносятся пропорционально. Если на меньшей сетке проёмы совпадут, сначала разнесите или удалите их.
4. «Пройти от первого лица» открывает текущий лабиринт. «Сгенерировать и пройти вслепую» применяет параметры и сразу скрывает карту, не показывая новый план.
5. Нажмите «Начать прохождение» для Pointer Lock. WASD — движение, мышь — обзор, Shift — 2,8 м/с вместо 1,4 м/с. Esc — пауза, освобождение курсора. Вернуться к карте можно отдельной кнопкой.
6. Дойдите до внешней границы выходного проёма. После выхода карта покажет траекторию, маршрут-эталон, расстояние, время и отношение дистанций. При досрочном возврате отображается частичная траектория, без итогового отношения.
7. «Сохранить» / «Открыть»: нативные диалоги Tauri. Браузерная версия использует скачивание и выбор файла.

В разделе «Параметры конструкции» можно сразу изменить высоту стен (1,8–10 м), выбрать цвет (по умолчанию чёрный, `#000000`), включить галочку «Просвечивающая ткань» и сплошную непрозрачную крышу в цвет стен. При включённой ткани примерно 1% площади занимают мелкие просветы: они видны при взгляде прямо на полотно вплотную. Эффект плавно исчезает между 0,3 и 0,9 м и при взгляде под острым углом; издалека полотно непрозрачное. Без галочки стены полностью непрозрачные. Свет пропускается очень слабо, коллизии сохраняются. Каркас и крыша остаются непрозрачными. Панели сортируются по глубине при повороте камеры, оставаясь одним instanced mesh. Крыша покрывает весь участок на уровне верха стен. Настройки сохраняются при повторной генерации. Карта остаётся схематическим планом; эффект ткани виден в 3D.

Таймер учитывает время активного захвата мыши, включая остановки для выбора пути. Пауза и скрытая вкладка не учитываются. Траектория и результат хранятся в памяти до новой генерации/загрузки; JSON сохраняет сам лабиринт.

## Модель, метрики и допущения

- Координаты мира: X вправо, Z вниз по карте, Y вверх; единица — метр. Размер модуля — расстояние между осями его угловых опор. Ширина промежутка между модулями задаётся отдельно; опоры выступают в него максимум на 0,06 м с каждой стороны. Высота стен настраивается, по умолчанию 2,5 м; толщина полотна в коллизиях 0,06 м. Высота глаз 1,7 м, радиус посетителя 0,25 м.
- В модульной конструкции граф включает внутренность каждого модуля, проходы между модулями и их пересечения. Для N × M модулей получается (2N−1) × (2M−1) узлов. Пространственные полосы чередуются: модуль / проход / модуль. Размер участка по каждой оси — `число модулей × размер модуля + (число модулей − 1) × ширина прохода`.
- Генератор работает на **полном графе** этих пространств. Полотно может закрывать любую сторону модуля и любой промежуток между соседними опорами, в обоих направлениях. Проходы между модулями не оставляются автоматически свободными. Без дополнительных соединений получается связное дерево без циклов; дополнительные соединения открывают оставшиеся внутренние панели и добавляют циклы. Метрики и BFS используют ту же топологию, что геометрия и коллизии.
- Вход слева первого модуля, выход справа последнего. Отдельной внешней ограды и обходного кольца нет: крайние панели расположены на сторонах крайних модулей и между их опорами. На границе посетитель остаётся внутри участка; выход засчитывается только у выходного проёма.
- Все случайные решения генерации используют FNV-1a + Mulberry32. Кнопка нового seed меняет только входную строку seed. В классической сетке остов и дополнительные связи работают по прежним правилам.
- Коридоры — рёбра графа, тупики — вершины степени 1, развилки — степени ≥ 3. Независимые циклы: `E − V + C`; число компонент вычисляется отдельно, в том числе у несвязного загруженного файла.
- BFS находит кратчайший **маршрут графа по центрам клеток**. Длина включает отрезки от входной границы до центра и от центра до выходной границы. Отношение к площади имеет размерность м/м².
- Записанный свободный маршрут может срезать углы. Поэтому отношение реальной дистанции к эталону иногда меньше 1: эталон не является непрерывным геометрическим минимумом.
- Коллизии — круг против прямоугольных стен, пространственная индексация, подшаги ≤ радиуса/4 и раздельное движение по осям для скольжения. Большие перемещения не туннелируют сквозь стену. Не используется физический движок.
- У каждого модуля четыре собственные угловые опоры из двух перпендикулярных досок, четыре верхние перекладины и диагональные укосины. Между модулями нет соединяющих деревянных перекладин, но может быть натянута стенка из полотна. Любая панель опирается концами на существующие угловые опоры; дополнительных стоек внешнего ограждения нет. Опоры имеют консервативную область коллизии 12 × 12 см; укосины расположены выше глаз, а у минимальной высоты стен не устанавливаются. Проходы шириной 0,8 м остаются проходимыми. Классические файлы сохраняют прежний общий каркас сетки.
- Доски и крепёж объединены в instanced mesh: количество draw calls не растёт с числом модулей. Фактура дерева и травы создаётся локально, без загрузки внешних изображений. Тени солнца следуют за посетителем в ограниченной области 32 × 32 м. Three.js загружается при первом открытии прохождения. Карта — Canvas 2D с масштабом под размер окна.
- Ориентиры на карте и в 3D: перемещаемая лесная полоса и солнечный диск с положением по московскому времени в августе. Направление диска совпадает с направлением дневного света и теней. Лес не зависит от seed лабиринта; положение солнца сохраняется относительно сторон света при ходьбе и поворотах камеры. Стены и крыша заслоняют ориентиры с учётом режима просвечивающей ткани. Дальность камеры и тумана учитывает размер участка.
- Существующие здания, редактирование стен, строительные чертежи и автоматическая оценка «интересности» в MVP не входят. Расчёт эвакуации, нагрузок и пригодности конструкции для мероприятия не реализован.

## Формат JSON v1 / v2

Сохраняются `version`, `parameters` (алгоритм, seed, сетка, ширина прохода, дополнительные соединения, опциональный `moduleSize`), `width`, `depth`, `wallHeight`, `wallColor` (`#RRGGBB`), `translucentFabric` (галочка ткани; по умолчанию false), `roof` (логическое значение), полные списки смежности `passages`, `entrance` и `exit` (`cell`, `side`). Новые модульные лабиринты используют **v2**, без внешнего обходного кольца. Классическая сетка сохраняет v1. Ранее записанные модульные файлы v1 открываются с их исходными размерами и геометрией; повторная генерация переводит схему на актуальную v2. Старый `wallOpacity` преобразуется в галочку: значения меньше 1 включают эффект ткани; непрозрачные старые файлы остаются непрозрачными. Файлы v1 без цвета и крыши загружаются с чёрными стенами и открытым небом. Загрузка восстанавливает топологию из списков, **не запускает генератор заново**. Проверяются версия, размеры, параметры конструкции, типы, соседство, симметрия рёбер, отсутствие повторов и положение проёмов на границе. Лимит файла 5 МБ. Несвязные графы допустимы; недостижимый выход обозначается на карте и блокирует прохождение.

## Структура

```text
src/core/          модель, PRNG, граф, BFS, метрики — без DOM/React/Three/Tauri
src/generators/    backtracker, prim, дополнительные соединения
src/simulation/    коллизии, игрок, запись траектории — без UI
src/renderer/      Three.js, instanced стены, дневная сцена
src/ui/            React-обёртки карты/прохождения, Canvas 2D
src/persistence/   валидация JSON отдельно от нативных/браузерных файлов
src/main.tsx       React-приложение, параметры и режимы
src-tauri/         минимальный Rust host, capabilities, иконки
tests/            Bun unit/integration tests доменного ядра
scripts/          отдельная проверка UI через Playwright
```

## Проверки интерфейса

При запущенном `bun run dev` и установленном Microsoft Edge:

```sh
bun run scripts/browser-check.ts
bun run scripts/fabric-check.ts
```

Для browser-check можно задать `MAZE_BROWSER` с абсолютным путём к Chrome/Chromium. Скрипт проверяет генерацию, масштаб, 3D, Pointer Lock, прохождение 1×1, результаты, JSON round trip, 100×100 и узкий экран. Отдельный fabric-check использует Edge и измеряет реальные пиксели шейдера: около 1% светопропускания на 0,28 м, полную непрозрачность на 2 м и при выключенной галочке. Скриншоты сохраняются в `test-results/` и не входят в Git. Для macOS укажите путь к Chrome для browser-check; системный WebKit Tauri этим скриптом не проверяется. Нативные диалоги и поведение системного WebView требуют отдельной desktop-проверки.
