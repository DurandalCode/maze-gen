# Maze Lab — веб-прототип

Рабочий цикл: **сгенерировать → изменить в редакторе → пройти → сохранить → загрузить**. Текущий объём и чек-лист: [WEB-PROTOTYPE.md](docs/reboot/WEB-PROTOTYPE.md).

## Запуск и общая библиотека

Нужны Node.js 22 и Bun 1.4.4. Зависимости закреплены в bun.lock.

```sh
bun install --frozen-lockfile
./start-web.command
```

Откройте [библиотеку](http://127.0.0.1:1421/) или сразу [Первый маршрут](http://127.0.0.1:1421/?route=first-route).

`start-web.command` запускает dev-сервер с общей библиотекой. Карты, черновики, прохождения и записанные траектории хранятся в `.local-data/shared-library.json`. Они доступны во всех браузерах этого компьютера. Подтверждение сохранения приходит после атомарной записи JSON; видимые списки обновляются раз в 5 секунд.

Прежняя локальная IndexedDB-библиотека переносится один раз при первом подключении. Локальные оригиналы сохраняются. Конфликтующие проекты/попытки при переносе получают отдельные копии. После перезапуска сервера незавершённые попытки доступны с последнего подтверждённого checkpoint.

Сервер привязан к 127.0.0.1. Одну активную попытку ведите в одном браузере: конфликтующие записи одной sequence отклоняются, а не перезаписываются. Файл общей библиотеки не входит в Git. Для переноса на другой компьютер скопируйте его при остановленном сервере или используйте JSON-экспорт.

Статический `bun run build && bun run preview` без dev-сервера использует прежнее локальное IndexedDB-хранилище. `MAZE_SHARED_LIBRARY=0 bun run dev` явно включает локальный режим.

## Пользовательский сценарий

1. **Создать лабиринт** → 12 или 30 комнат → **Сгенерировать**. Размер и seed определяют результат.
2. Откройте карту в редакторе. Выбирайте комнаты на плане, меняйте числовые параметры или перемещайте мышью. **Отменить** восстанавливает изменение. Ошибки остаются в черновике; Play доступен после проверки актуальной карты.
3. **Пройти** сохраняет проверенную карту. Откроется отдельная карточка с планом/3D, геометрией, материалами, параметрами генерации и историей попыток. **Начать прохождение →** запускает игру одним нажатием. WASD — движение, стрелки — поворот, мышь — осмотр, Esc — пауза.
4. **Пауза → Завершить попытку → Остановить и сохранить** сохраняет прерванное прохождение. Достижение выхода завершает его автоматически. Во вкладке **Прохождения** доступны записи и восстановление.
5. **Экспорт карты / Экспорт попытки** скачивает самодостаточный JSON. **Импорт JSON** проверяет и загружает пакет. Черновик отдельно скачивается из редактора.

## Маршруты из файлов

Каталог готовых карт — `public/routes/index.json`. Файл маршрута — `public/routes/<id>.json`: обычный пакет экспорта с одной картой, без проектов и попыток. Vite отдаёт его в dev-режиме, build копирует в dist/routes.

Ссылка `/?route=first-route` загружает `public/routes/first-route.json`, проверяет формат, геометрию и путь, затем открывает полную карточку лабиринта. Просмотр карточки не создаёт попытку; она появляется только после явного запуска. Постоянный адрес `/?map=<hash>` можно скопировать кнопкой «Скопировать ссылку». В общей библиотеке он открывает ту же карту в другом браузере. Маршрут сохраняется в текущую библиотеку только при отсутствии такой ревизии; существующее локальное название не перезаписывается. Ручной импорт не требуется. После изменения JSON повторно откройте ссылку; для статического preview предварительно пересоберите dist.

## Возможности и ограничения

Публичный генератор: одно связное ортогональное дерево из 12 или 30 комнат 2×2 м на площадке 20×20 м. Проёмы 1.4 м, коридоры 0.4 м. Все готовые карты проходят общую физическую проверку и проверку маршрута.

Другие формы, отдельные стены и проёмы доступны вручную в редакторе. Автогенерация циклов, произвольной площадки, покрытие 65% и пределы хода 12/20 м не входят в этот профиль. Маршрут-эталон приблизительный. Большие карты, Android и исследовательский рейтинг отложены. Универсальный frontier-поиск сохранён в исходниках и скрыт из интерфейса.

## Проверки и разработка

```sh
bun run dev
bun run check
bun test tests/unit
bun run build
bun run format:check
bunx playwright install chromium --no-shell
bun run test:e2e
bun run test:e2e --config=playwright.shared.config.ts
```

Остановите пользовательский сервер перед тестами: основная функциональная регрессия сама занимает порт 1421 и явно использует отдельные локальные browser contexts. Общая библиотека проверяется отдельно на порту 1422 с тестовым JSON в work/. Большая PERF-03 M-50/M-100 проверка — opt-in через MAZE_LARGE_PERF=1; прежний отчёт сохранён.
