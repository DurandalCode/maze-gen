# Общая модель проверок v5/v7

Целевая модель одноэтажной геометрии — свободная v5; v7 расширяет её мостами.
Старые входные файлы сохраняются через слой совместимости. Двухэтажный режим
сейчас не переносим: его существующие карты и записи сохраняем без изменений.

## Перенесено

- Скрытность проёмов: один сертификат на реальных ориентированных отрезках,
  полной полезной ширине проёмов и физических стойках. Сеточный алгоритм
  удалён. Старый вход адаптируется в геометрическую сцену в `compat/`.
- Лучи обзора: обход клеток лабиринта и проверка соседства заменены реальными
  панелями/стойками и пространственным индексом в метрах. v7 использует
  существующую 3D-геометрию перекрытий и мостов.
- Проверки маршрута, циклов/компонент, изменённого seed, границы входа,
  больших шагов и четырёх направлений прохождения выполняются на v5.
- Старые `portal-privacy.test.ts` и `spatial-perception.test.ts` удалены
  после замены всего их покрытия нативными v5/v7 сценариями. Шесть
  соответствующих случаев из `core.test.ts` заменены общими проверками;
  два случая ограничения движения объединены без потери условий.
- Декодирование v1–v4 выделено из общего JSON-входа в `compat/legacy-maze.ts`.
  Поддержка чтения, валидация и идентификаторы сохранённых данных сохранены.

Перенос выявил ошибки: поиск свидетеля видимости только по закрытым стойками
краям; неполный учёт полезной ширины; ложная критичность первого экрана при
наличии второго; микроскопический выход за границу с записью мнимого пути;
отсечение длинного шага в невыпуклой области по неверному предположению
монотонности. Добавлены регрессии, проверки не ослаблялись.

Старый валидатор геометрии размещения получил локальный индекс фактических
регионов. Это сохраняет прежние фильтры и временной бюджет больших
коридорных подборов во время миграции. Индекс создаётся на каждый вызов,
поэтому изменения существующих объектов регионов не оставляют старые данные.

## Остаётся перенести

- Генераторы ещё создают старые промежуточные структуры для сеточных режимов.
  Их проверенные алгоритмы и возможности сохраняются; следующий переход —
  выдача свободной геометрии на границе генерации.
- Старые файлы пока декодируются в прежние структуры, а затем используются
  адаптерами. Для существующей серверной библиотеки есть разовый перенос
  (см. ниже). Автоматический перенос произвольных импортов и браузерной
  IndexedDB пока не включён. Старые немодульные карты и размеры вне
  ограничений v5 требуют отдельной работы; ошибку нельзя обходить масштабированием.
- Часть старых ветвей в `core/`, расчёте критических стен и подробной оценке
  коридоров/сложности остаётся нужна этим производителям и двум этажам.
  Удалять их следует после переноса соответствующего покрытия и потребителей.
- Проверки генераторов и совместимости старого импорта, а также уникальные
  проверки высоты v7 сохраняются: это не дубли геометрических тестов v5.

## Разовый перенос библиотеки

`bun scripts/migrate-library.ts source-directory [another-source] --out new-directory`

Результат публикуется только после проверки всех переносимых карт и записей:

- `backup/0`, `backup/1`, … — неизменённые исходные библиотеки;
- `library/` — готовая новая библиотека для `MAZE_DATA_DIR`;
- `manifest.json` — таблица старых/новых ID и количества перенесённых записей.

Исходные каталоги не изменяются; существующий каталог результата не затирается.
Одноэтажные v1–v4 преобразуются существующим конвертером с проверкой схемы,
физической проходимости, совпадения панелей, координат всех проёмов и выбранной
пары вход/выход. Сохраняются названия, даты, статусы, причины отклонения и
исторические оценки прохождений. ID карт пересчитываются по новой модели,
ссылки записей и физические идентификаторы обновляются вместе. Все координаты,
время, длина и ID самих записей остаются прежними. Повреждённые данные или
конфликт метаданных прерывают перенос целиком, без частично готовой библиотеки.

v5/v7 и двухэтажные v6 копируются с прежними ID и содержимым, без декодирования
и пересчёта геометрии. Одинаковые карты из нескольких библиотек с одинаковыми
названием и статусом объединяются: дата создания — самая ранняя, изменения —
самая поздняя. Исходные даты каждой копии остаются в резерве. Никакие генераторы
разовый перенос не запускает.
Встроенные JSON-наборы приложения и отдельные браузерные хранилища эта
серверная утилита не меняет. Импорт старых файлов остаётся доступен.

На реальной старой карте с залами найдены и исправлены два дефекта конвертера:
повторный учёт площади зала поверх крайних модулей 2×6 и ложные стойки на
технических разрезах коллинеарной стены. В v5/v7 модуль внутри зала может быть
каркасом (`frameOnly`): он остаётся в конструкции и ведомости модулей, но не
создаёт отдельную комнату/тупик. Такой каркас должен оставаться внутри зала.
`preservedSupports` хранит реальные исходные стойки; новые ручные стены и мосты
по-прежнему получают свои опоры. «Перестроить стены» сбрасывает сохранённые
панели и стойки вместе. Регрессия проверяет неизменность площади, графовых
метрик, панелей, стоек, сохранение JSON и маршрут с настоящими столкновениями.
Геометрия соединения при проверках пересечений вычисляется один раз за вызов
валидации; кэш не переживает изменения черновика.

После переноса: `MAZE_DATA_DIR=/absolute/new-directory/library bun run serve`.
Реальные браузерные сценарии новой библиотеки:
`MAZE_TEST_URL=http://127.0.0.1:1422 bun scripts/library-migration-check.ts new-directory`.

Это не объявляет завершённой миграцию всего runtime.
