# Исследовательская модель сложности и симулятор посетителей

Статус: **design proposal для новой версии Maze Lab**, не описание реализованного алгоритма. Не путать с историческими моделями v5–v11, и с **JSON v5**, который обозначает формат свободно размещённых карт.

## Определения

Три слоя и никакого знания решения у агента:

1. `PhysicalLayout`: непрерывная геометрия стен, стоек, крыши, этажей, проёмов, лестниц, мостов. Метры; единая система координат. Верхний коридор над нижним **не образует** ребра перехода без лестницы/соединения.
2. `NavigationGraph`: достижимые пространства/точки выбора/проёмы, ориентированные переходы с физической длиной и уровнем. Геометрические служебные вершины не должны искусственно повышать число развилок.
3. `ObserverView`: видимые проёмы, перспективы, ориентиры, расстояния и доступный финиш, полученные трассировкой видимости из допустимых положений глаз с учётом крыши и стен.

Два графа не следует путать: **проходимость** (где можно идти) и **видимость** (что можно узнать). Взаимная видимость не означает проходимость. Мост сверху и коридор под ним связаны визуально/акустически только если это действительно допускает геометрия.

## Состояние агента

```ts
type MazeObservation = {
  visiblePassages: Array<{ id: string; bearing: number; apparentDepthM: number }>;
  visibleLandmarks: Array<{ id: string; bearing: number; confidence: number }>;
  visibleGoal?: { bearing: number; distanceEstimateM?: number };
  localGeometry: unknown; // локальные стены/проёмы; никаких скрытых рёбер
};

type AgentBelief = {
  estimatedPose: { x: number; z: number; floor: number; headingRad: number };
  uncertainty: { positionM: number; headingRad: number };
  visitedLandmarks: Map<string, unknown>;
  discoveredGraph: unknown; // только реально увиденные/пройденные переходы
  strategy: string;
  rngState: unknown;
};
```

Структуры иллюстративные, не API-контракт существующего кода. Состояние агента **не должно включать** `shortestPathToGoal`, скрытые рёбра, весь план, координаты «истинной» цели, если их не дали участнику условия задачи. `truePose` хранит только движок для физики и оценки ошибок.

Отдельно задавать:
- `goalKnowledge: none | bearing | approximate-position | exact-position`;
- `boundaryKnowledge: none | outer-outline`;
- видимость ориентиров, крыши и неба;
- точность распознавания знакомого места;
- дрейф курса, память, риск повторной проверки и предпочтение длинных перспектив.

## Агентные базовые линии

Базовые агенты нужны не как «модели человека», а как тесты обходимости:
- `left-hand`, `right-hand`: геометрическое непрерывное следование выбранной стене, включая лестницы и окончания. Проверка возможного цикла по состоянию (положение, направление, контакт с границей), а не по одному посещённому узлу.
- `random-walk`: случайный выбор с явным бюджетом шагов/времени.
- `trémaux-like`: помечает рёбра по мере исследования, умеет возвращаться; используется как тест решаемости, не как имитация среднего гостя.
- `heading-greedy`: ориентируется на известное/предполагаемое направление цели, не имеет полного графа.
- `frontier-memory`: исследует ещё неизвестные продолжения, запоминает проёмы и обнаруженные петли.
- `bridge-seeker` / `under-bridge`: альтернативная эвристика «ищи переход/проходи под ним». Мост двусторонний, обнаружение обратного входа считается законным.

## Не делать одну общую оценку сложности

Возвращать **вектор наблюдений** и распределения по агентам, не просто `difficulty: 87`:

- `completionRate@budget`: доля успешных попыток при указанном лимите;
- `distanceRatio`: фактические метры / эталонная кратчайшая **физически допустимая** длина; графовый эталон явно маркировать приближением;
- `firstWrongTurnM`, `wrongBranchDepthM`, `revisitDistanceM`;
- `visitedAccessibleAreaRatio`, `unseenAreaM2`;
- `decisionCount`: **значимые** развилки, а не вспомогательные вершины;
- `headingErrorDeg`: ошибка курса, когда была запрошена оценка направления;
- `recognitionConfusions`: признание разных мест одним и тем же / незнакомого знакомым;
- `bridgeTraversal`: входы сверху, проходы снизу, время поиска лестницы, факт выхода к цели;
- `wallFollowerResult`: success / loop / timeout / invalid.

Теоретические графовые признаки отдельно:
- `E - V + C` независимых циклов, с подсчётом связных компонент;
- размеры и точки входа в двусвязные блоки; доля очевидных тупиков из развилок;
- кратчайшая дистанция до цели и глубина альтернатив;
- BFS expanded nodes (как полезный proxy из Valenzuela et al., **не** как мера человеческого опыта);
- визуальная степень развилки и длина видимой перспективы (isovist/LOS).

## Отдельные модельные ошибки, выявленные в проекте

[Исторические наблюдения](../human-navigation.md) показывают, что прогноз часто был значительно длиннее реального прохождения, а добавленные циклы нередко не проходились целиком. Поэтому:
1. Не поощрять «модель прошла много километров» без сравнения с людьми.
2. Видимые терминальные карманы можно отвергать **до** физического посещения; не приписывать агенту разведку заведомо видимого тупика.
3. Различать однократный ложный выбор, полноценное завершение цикла и осознанный исследовательский обход.
4. Не обучать одну универсальную «длину памяти 12 м» на нескольких прохождениях; это гиперпараметр до калибровки.
5. При оптимизации пользоваться несколькими независимыми агентами и реальными записями **не из обучающего набора**.

## Проверки/контракт перезапуска

- Геометрия и достижимость совпадают между редактором, игровым движком и анализатором; каждый переход проходит collision-check.
- Одно seed + версия генератора + параметры = тот же граф и та же геометрия.
- Нет утечки решения в `MazeObservation`; тесты с перестановкой скрытых рёбер должны давать идентичные наблюдения до обнаружения этих рёбер.
- Каждый мост — отдельное ребро маршрута на своём уровне; перекрестье сверху/снизу без лестницы НЕ создаёт соединение.
- Для обратимого моста существует обратное прохождение, если физика не вводит обоснованное ограничение.
- Каждый граф проверяется `trémaux-like` на достижимость/исследуемость; left/right-hand — на цикл и успех.
- Для набора контрольных карт выдавать фиксированную телеметрию по всем стратегиям; при изменении версии параметров повторно считать **весь** benchmark.
- Версии `mapSchemaVersion`, `generatorVersion`, `agentModelVersion`, `metricVersion`, `observationVersion` хранить отдельно. Нельзя интерпретировать смену формата v5 как «обновление модели v5».

## Минимальный критерий приёмки новой модели

Она **не обязана** идеально предсказывать время каждого человека, но должна:
1. уважать физическую геометрию и неполную информацию;
2. сохранять воспроизводимость;
3. предсказывать лучше тривиальной baseline-модели на отложенных картах/испытуемых по заранее выбранной ошибке;
4. публиковать неопределённость и различия профилей;
5. не называть плохое прогнозное качество «сложностью лабиринта».
