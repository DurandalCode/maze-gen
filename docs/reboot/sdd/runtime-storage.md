# Контракты исполнения, хранения и пользовательских сценариев

Область: первый рабочий выпуск. Связанные документы: [geometry.md](geometry.md), [generator.md](generator.md), [acceptance.md](acceptance.md).

## Worker-протокол

Envelope запроса: protocolVersion=1, jobId, ownerId, sourceRevision, operation, input, deterministicBudget. Ответ: те же идентификаторы, kind=progress/result/error/cancelled, payload. Result содержит hashes и версии производных данных. Worker не пишет в React-состояние и не меняет исходный Document.

Для операций без документа (list/import/export) sourceRevision=null; ownerId привязан к запросу экрана, jobId всё равно обязателен. Числовые размеры и протокол проверяются до чтения payload. Данные native bridge передаются только из доверенного встроенного origin.

Операции compute-worker: compile, validate, navigation, generate, metrics; позже observe/analyze. Операции storage-worker: list/get/save, chunk append/finalize, validate/import/export. Один compute-worker и один storage-worker в v1; на Android тяжёлый анализ отсутствует. Очередь compute ограничена одной текущей работой и последней ожидающей ревизией на owner. Устаревшие промежуточные правки объединяются; потеря пользовательских команд истории не допускается.

Состояния Job: queued → running → completed/failed/cancelled. Один terminal outcome. При terminate текущий job закрывается как cancelled, новый worker создаётся лениво; ID не переиспользуются. Result принимается только при совпадении jobId, sourceRevision и ожидаемой операции. После unmount/смены документа owner снимает подписки.

Typed arrays передаются как transferable копии/артефакты; нельзя detatch буфер, ещё нужный рендеру. Крупный результат передаётся один раз, progress не содержит полного документа. Буферы освобождаются при отмене/замене. Ошибка worker не закрывает проект и допускает повтор.

## Репозиторий

IndexedDB `maze-reboot-v1`, schemaVersion=1. В браузере ребут использует отдельный origin/порт разработки 1421, на Android отдельный applicationId. Удаление/перезапись старых баз не производится.

| Store | Ключ | Содержимое и индексы |
|---|---|---|
| projects | projectId | Название, currentRevisionHash, createdAt, updatedAt, optional originId для импортированной копии; индекс updatedAt+id |
| drafts | projectId | Последний подтверждённый редактором черновик, commandRevision, baseRevisionHash |
| definitions | contentHash | Immutable определение модуля |
| maps | revisionHash | Immutable документ без встроенных дубликатов definition bodies, список зависимостей |
| mapSummaries | revisionHash | Имя/габариты/числа объектов/статус/updatedAt; индексы updatedAt+hash, titleNormalized+hash |
| sessions | sessionId | mapHash, condition, state, elapsed/distance, lastCommittedSequence, lastSample, timestamps |
| walkSummaries | sessionId | Компактные поля списка и статуса; индексы updatedAt+id, mapHash+updatedAt+id |
| walkChunks | [sessionId,sequence] | Отсчёты и события, contentHash; индекс sessionId+sequence |
| analyses | analysisKey | map/session hash, версии, условия, бюджет, результат; не загружается списком |
| importStaging | importId+entityKey | Проверенные staged сущности; не видны библиотеке до коммита |

Сохранение maps/definitions/summaries и переключение указателя проекта атомарно в одной транзакции. Сбор и hash/валидация выполняются до открытия write transaction: транзакция не ждёт произвольных async-вычислений. Подтверждение UI после transaction.complete. Ошибка оставляет прежний указатель и показывает retry/export-draft.

`listMaps/listWalks({cursor,limit,sort,filter}) -> {items,nextCursor}`: default limit 30, max 100. Cursor содержит последнюю составную ключевую позицию, сортировка стабильна по ID при равных датах. Запрещён getAll тел maps/walkChunks для списка. Поиск по имени/статусу обходит только summaries, порциями и отменяемо; серверный полнотекстовый движок не нужен. Карты и попытки загружаются независимо, общий Promise.all не скрывает готовый список.

`getMap(hash)` загружает документ с определениями и передаёт compute-worker для валидации/подготовки; кешируется по immutable hash. `getWalk(id)` сначала возвращает заголовок, chunks читаются последовательно; анализ и трасса не блокируют список. Повреждённая запись получает локальную ошибку и возможность экспортировать исходный JSON, остальные доступны.

## Запись прохождения

Session state: prepared → running ↔ paused → finished/stopped; после перезапуска незавершённая сессия становится interrupted и может быть продолжена с последнего подтверждённого положения либо завершена пользователем. Продолжение сохраняет sessionId и непрерывную sequence, пауза не добавляет время активного движения. terminal state не откатывается поздним chunk.

Подготовка: записать неизменяемую ревизию карты, условия, session header; только после успешного коммита начинать попытку. При недоступном хранилище предлагается явно обозначенное прохождение без сохранения; приложение не показывает ложный статус «сохранено».

Отсчёт: activeTimeMs, x/y/z, yaw/pitch, inputMode; измерение дистанции — каждый физический шаг, сериализация отсчётов 10 Гц и на событиях входа/выхода/паузы/поворота в контакте. События и accumulatedDistance хранятся отдельно, длина не восстанавливается только по редкой полилинии. Координаты не раскрываются агенту через ObserverView.

Flush каждые 2 секунды или при 256 samples, затем на pause/finish; chunk sequence монотонна. Один неподтверждённый flush и ограниченная очередь до 5 chunks; при её заполнении запись/прохождение ставится на паузу с ошибкой, не растёт без ограничения. Повтор [sessionId,sequence] с тем же hash — no-op, с другим — CONFLICT. Store write chunks+session summary одной транзакцией; пропуск sequence отклоняется и вызывает повтор отсутствующей части.

Finish ждёт коммита последнего chunk и terminal state, допускает retry; UI может показать финиш сразу с состоянием «Сохраняется». На Android background сначала прекращает движение и запрашивает flush, однако гарантией остаются периодические коммиты. Восстановление перечисляет подтверждённые chunks, не перестраивает всю карту для каждой части. Обработчики событий и RAF снимаются при закрытии сцены.

## JSON-обмен

Envelope: kind=`maze-reboot-package`, schemaVersion=1, exportedAt, definitions[], maps[], projects[] (необязательно), sessions[], chunks[], manifest{counts,entityHashes}. Экспорт выбранной карты или попыток включает замкнутое множество зависимостей; сохранённые analyses опциональны и версионированы. Данные старых форматов не мигрируются.

Предельный размер одного файла — 32 MiB UTF-8 в v1. Лимиты: не более 100 карт, 1000 попыток, 1 000 000 samples на пакет; также действуют лимиты геометрии. Большой выбор разбивается на независимые пакеты с полными зависимостями; UI показывает число пакетов и подтверждённые экспорты. Android не передаёт многомегабайтный JSON одним синхронным bridge-вызовом в потоке рендера: экспорт идёт из storage-worker через ограниченные части в временный файл нативной оболочки, затем sharesheet. Каждая часть подтверждается, отмена очищает только созданный временный файл.

Bridge-протокол: begin(exportId,filename,expectedBytes), append(exportId,sequence,chunk), finish(exportId), abort(exportId). Размер chunk ≤256 KiB UTF-8, максимум 2 неподтверждённые части; запись файла на нативном executor. UI лишь пересылает ограниченные сообщения. sequence и итоговый размер проверяются; sharesheet открывается после finish. Если одна карта/попытка с полными зависимостями превышает лимит пакета, экспорт сообщает ITEM_TOO_LARGE и не создаёт усечённый файл; формат многотомной одной попытки — отдельное расширение.

Импорт: размер файла → JSON parse в worker → schema/limits → hashes/dependencies → geometry validation → предварительный итог counts/conflicts → staging → единый коммит в рабочие stores. Существующее приложение продолжает работать со старой библиотекой до коммита. Для схемы v1 неизвестные обязательные поля/примитивы отклоняются; поля расширений допускаются только в `extensions` и не исполняются.

Отмена во время write transaction вызывает abort, если коммит ещё не завершён. Если complete уже наступил, результат — «импорт завершён», а не ложное «отменено»; rollback после коммита требует отдельного действия. После аварийного завершения неприменённые staging-записи удаляются при следующем запуске, не затрагивая рабочие stores.

Точный дубликат immutable hash пропускается. Одинаковый заявленный hash и другое содержимое — повреждение. Один projectId с другой ревизией по умолчанию импортируется копией с новым ID и пометкой происхождения; существующий проект не заменяется. SessionId с одинаковой последовательностью chunks/condition — duplicate; отличие тела — conflict, импорт как новая попытка с originId по явному выбору. Семантический конфликт предлагается до коммита; отмена не меняет рабочую библиотеку. Крупный пакет не принимается частично незаметно.

## Сценарии интерфейса

| Экран/сценарий | Обязательное поведение |
|---|---|
| Библиотека | Независимые вкладки Карты/Прохождения, поиск, сортировка, фильтр статуса, первая страница 30; следующая подгружается кнопкой/скроллом |
| Карта | Пройти вслепую, Посмотреть, Экспорт; на ПК Редактировать; попытки по этой карте; переименование проекта без смены геометрии |
| Слепой вход | Нейтральное имя/ID, без миниатюры плана, seed и типа ловушки; после явного просмотра записывается previewed=true для последующих попыток на этом устройстве |
| Просмотр | 2D/3D, размеры и физические метрики; загрузка выбранной карты имеет собственный прогресс/отмену |
| Прохождение | Полный экран, управление платформы, пауза/выход, состояние записи; анализ и план не показываются во время слепой попытки |
| Редактор ПК | Каталог слева, план/3D, свойства выбранного объекта; invalid draft редактируется/сохраняется, Play доступен только для проверенной ревизии |
| Генерация | Сценарий generator.md, варианты появляются независимо, открытый проект заменяется только по выбору |
| Импорт | Выбор файла, прогресс, итог, конфликты, применить/отмена; повторный импорт явно сообщает о дубликатах |
| Восстановление | Незавершённая попытка и черновик доступны после запуска; результат сохранения отличим от индикатора процесса |

Слепота не является технической защитой от пользователя, который уже видел карту на другом устройстве; previewed и сведения об опыте — записываемые условия исследования. Удаление проектов/попыток выполняется отдельным действием с подтверждением и перечислением затрагиваемых записей; immutable maps/definitions удаляются только при отсутствии ссылок и после коммита. Случайное удаление одной карты не каскадирует на чужие попытки.

Мобильные элементы управления минимум 44 CSS px; сенсорный просмотр не требует hover. Потеря WebGL-контекста ставит движение на паузу, сохраняет подтверждённую сессию и предлагает восстановить сцену без перезапуска попытки.

## Оракулы исполнения и хранения

- RUN-01: stale result после новой правки/отмены игнорируется; terminal event единственный; число worker/подписок не растёт после 20 циклов.
- DB-01: список 100 карт/1000 попыток не обращается к maps/chunks; первый список показывается при отказе загрузки второго.
- DB-02: сбой транзакции save/import оставляет прежние указатели/summary; повтор не создаёт дублей.
- REC-01: последовательность chunk, повтор, поздний checkpoint после finish, восстановление interrupted и заполнение очереди дают определённые состояния.
- IO-01: пакет со смешанными формами переносится ПК→APK→ПК без каталога; hashes и условия совпадают.
- IO-02: старый формат, превышение размера, неизвестная форма, повреждённый hash и конфликт project/session не перезаписывают данные.
- UX-01: слепой старт не раскрывает план; закрытие загрузки не закрывает библиотеку; поиск не блокируется загрузкой одной карты.
