# План реализации и контрольные точки

Статус: **готов к началу реализации**, 2026-11-11. Требования — [spec.md](spec.md), решения — [decisions.md](decisions.md), исполнимый список — [tasks.md](tasks.md). Реализация и измерения ещё не выполнены.

## 0. Bootstrap и контракты в коде

B-01, B-02, G-01…04. Создать новое приложение в корне репозитория, описать целевые визуальные сцены, реализовать декларативный каталог/документ и проверить kernel на смешанных формах. Старые отслеживаемые файлы удалены по решению пользователя; история Git сохраняет их без копии в активном проекте. Снятие старого baseline не требуется перед началом. Игнорируемые файлы сохранены по просьбе пользователя и не подключаются к исходникам ребута; данные не мигрируются.

Gate A: rectangle/triangle/circle проходят геометрические оракулы, проёмы и конструкция согласованы. Провал kernel закрывается в G-03 до распространения дефекта.

## 1. Сквозной прототип ПК и Android

N, J, R, DB, REC, IO, UX, APK, B-03 → QA-01. Фиксированные карты, полный 3D-вид, движение, запись частями, быстрая библиотека и JSON; APK на реальном устройстве. Генератор пока не нужен.

Gate B: ПК экспорт → APK импорт → прохождение → перезапуск → экспорт попытки → ПК просмотр. Одновременно VIS-01 и целевые PERF на M-50; M-100 — отдельный отчёт масштабирования. Отсутствие телефона не блокирует независимые задачи, но gate B остаётся открытым.

## 2. Редактор ПК

E-01…04. Команды/патчи, локальный preview, произвольные формы каталога, проёмы/соединения, сохранение черновика и проверенная revision для Play. E-01…03 доступны до gate B по зависимостям; E-04 завершает интеграцию после QA-01.

Gate C: mixed карта редактируется без полного пересчёта на pointer move; undo/recovery сохраняют данные, invalid draft не выдаётся за готовую карту. PERF-03 выполнен.

## 3. Генератор и первый рабочий выпуск

GN-01…06 → QA-02/03. Основной режим — использовать площадку, 3 варианта до 60 секунд. Контур/каталог/ограничения → tree/cyclic и free/orthogonal → progressive результаты → сравнение → редактор. Допустимость определяется физикой, без поведенческого рейтинга.

Gate D: детерминизм, отмена, определённый отказ, профили качества и PERF-10. Воспроизводимые веб-сборка и debug APK, JSON и отчёт по функциональным/визуальным/performance проверкам первого выпуска.

## 4. Исследовательские агенты

AN-01…04 после QA-03. ObserverView, baseline policies, физическое следование стене, метрики и отчёты по [analysis.md](analysis.md).

Gate E: отсутствует утечка скрытого плана, известные ответы на fixtures, completion/timeout/loop показаны честно. Модель пока experimental.

## 5. Валидация и оптимизация

AN-05, затем AN-06 только при validated. Протокол, участники, карты и holdout; критерий до эксперимента. При недостатке данных первый выпуск и baseline-отчёты работают, человеческий прогноз не получает ложного статуса проверенного.

Мосты и лестницы — FU-01 после одноэтажного выпуска. Первый выпуск не зависит от этого расширения.

## Начало и завершение

Начать с B-01, затем B-02/G-01. После схемы доступны G-02/G-03/J-01/DB-01. Дополнительных ответов пользователя для начала не требуется: рабочие настройки перечислены в decisions.md и могут корректироваться по измерениям с сохранением подтверждённых требований.

Завершение задачи — артефакт и указанная проверка. Фактические результаты пишутся в `reports/`; количество документации не доказывает скорость.
