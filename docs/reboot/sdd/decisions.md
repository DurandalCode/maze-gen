# Решения для начала реализации

Дата: 2026-11-11. Это технические решения и обратимые рабочие настройки, принятые при детализации SDD по поручению пользователя. Они не приписываются пользователю. Подтверждённые продуктовые ограничения находятся в [spec.md](spec.md). Менять решение следует вместе с зависимым контрактом и тестом.

## D-01. Граница первого выпуска

Первый рабочий выпуск: одноэтажная свободная геометрия, расширяемый каталог, редактор и генератор на ПК, просмотр/прохождение/библиотека на ПК и Android, запись попыток, JSON-обмен, APK. На Android генератор и подробный анализ пока не показываются. Простые физические и топологические метрики входят в первый выпуск.

Следующий исследовательский этап: наблюдения, агентные стратегии и отчёты; затем человеческая валидация и оптимизатор. Мосты — отдельное расширение после одноэтажного выпуска. Эти этапы имеют задачи, но не блокируют первый рабочий выпуск. Обещание научного прогнозирования сложности в первый выпуск не входит.

## D-02. Стек и размещение новой реализации

Сохраняем TypeScript strict, React, Vite, Three.js, Bun для тестов/сборки и Playwright для браузерных проверок. По прямому решению пользователя старое отслеживаемое приложение удалено из рабочей папки. Новая реализация начинается в корне репозитория: новые package.json, lockfile, tsconfig, Vite-конфигурация и src/. Старый код доступен только через историю Git (`ccd19ff`); запуск и снятие эталонов старого приложения не являются предварительным условием. По отдельному решению пользователя файлы вне Git сохранены; .tools, node_modules, dist и прежние сборочные артефакты не являются исходниками ребута. B-01 создаёт конфигурацию и зависимости по новой спецификации, без использования старых скриптов или скрытых настроек.

Папки нового `src/`: `domain`, `catalog`, `geometry`, `navigation`, `generation`, `observation`, `analysis`, `jobs`, `renderer`, `session`, `repository`, `platform`, `ui`. Ядро не импортирует React, DOM, Three.js, сервер старого приложения и `src/core/maze.ts`.

Для логических операций над полигонами используем адаптер над polygon-clipping; для триангуляции — earcut. Это узкие заменяемые зависимости. [polygon-clipping](https://github.com/mfogel/polygon-clipping) выполняет union/intersection/difference; [earcut](https://github.com/mapbox/earcut) триангулирует контуры с отверстиями. Валидация геометрии и проверка результата остаются нашими задачами; успешный вызов библиотеки не считается доказательством корректности.

Окончательную пригодность выбранной геометрической реализации проверяет ранняя задача G-03 на касаниях, узких проходах и смешанных формах. При провале меняется адаптер, публичные контракты сохраняются. Rust/WASM и смена 3D-движка нужны только при конкретном провале измеримого критерия.

## D-03. Платформы и доставка

ПК: браузер с локальным приложением, без зависимости от сервера библиотеки. Отдельный установщик Windows/Tauri отложен: пользователь подтвердил обязательную упаковку только для Android.

Android: Java/WebView, ресурсы приложения включены в APK, WebViewAssetLoader, системный выбор JSON и sharesheet. Для ребута отдельный applicationId `lab.maze.reboot`, отдельный origin/хранилище нового приложения; существующее APK и его данные не заменяются. Сохраняем текущий минимальный API 26 как начальную цель совместимости, поддержку WebGL2 и актуального WebView проверяем при запуске. Не объявляем все устройства API 26 соответствующими бюджету FPS.

Сборка разработки даёт подписанный debug APK. Release APK требует стабильного внешнего ключа подписи; ключи и пароли не включаются в репозиторий. Производственная подпись не блокирует начало разработки и проверку debug APK.

## D-04. Каталог

Формы задаются декларативными данными, отдельно от размещения. Поддерживаемые примитивы первого ядра: линии и круговые дуги. Контрольный каталог: квадрат 2×2, прямоугольник 2×6, равносторонний треугольник со стороной 4 м, круг радиуса 2 м. Размеры последних двух — тестовые значения разработчика, не утверждённый строительный каталог.

Для круглого контрольного модуля выбираем сегментированные стены и каркас; число секций определяется ограничением геометрической погрешности и попадает в физическую геометрию. Это явный первый профиль конструкции. Контракт сохраняет исходные дуги и позволяет позже добавить другой профиль реализации. Настоящий пользовательский редактор новых типов модулей не входит в первый выпуск.

## D-05. Начальный физический профиль

| Настройка | Значение |
|---|---|
| Высота стен | 2,5 м; диапазон редактора 1,8–10 м как в текущем приложении |
| Радиус игрока | 0,25 м |
| Высота глаз | 1,7 м |
| Номинальная ширина нового проёма | 1,4 м; ввод 1–3 м, дополнительно проверяется реальный просвет |
| Минимальный физический просвет | 1 м между фактическими препятствиями |
| Боковая сторона соединения / свободный пролёт | Не более 3 м |
| Штатные пролёты модуля 2×6 | Исключение до 6 м только в его определении |
| Доски каркаса | 0,12×0,04 м, профиль существующего приложения |
| Привязка редактора | Выключена; при включении 0,1 м / 15° |
| История | 100 команд; один жест — одна команда |

Проёмы учитывают толщину стен, стойки и каркас. Числа образуют версионированный профиль `physical-v1`; изменение профиля создаёт новую геометрическую ревизию, а не меняет старые попытки. Это правила модели приложения, перенесённые из локальной документации и кода, а не независимый расчёт строительных нагрузок.

## D-06. Генерация и ожидание

Пользователь подтвердил основной режим использования площадки и 3 варианта с ожиданием до 60 секунд на запрос. Дополнительный режим бюджета модулей — принятое рабочее решение. Подробный контракт в [generator.md](generator.md). Время watchdog не определяет успешный детерминированный результат.

Для первого выпуска структуры `tree` и `cyclic`; расположение `free` или `orthogonal`. Острова стен — измеряемое свойство физической конфигурации, а не синоним графового цикла. Вихревое размещение, заданные ловушки и оптимизация по поведению отложены до отдельных определений и проверок.

## D-07. Визуальная эквивалентность

Полный согласованный внешний вид обязателен. В первой реализации разрешены batching, пространственное разбиение, кеширование, управление частотой обновления теней и разрешением при прохождении визуальных критериев. Запрещено выполнять бюджет удалением леса, каркаса, ткани, крыши или просвечивания. B-02 описывает целевые сцены и visual checklist по сохранённым требованиям. Снятие старых скриншотов до очистки отменено пользователем; при необходимости отдельные сведения читаются из Git без возвращения legacy-кода в проект. Побайтовое визуальное совпадение без исходных снимков не объявляется доказанным. [acceptance.md](acceptance.md) задаёт условия сравнения.

## D-08. Данные и восстановление

Локальный IndexedDB-репозиторий одинаков по семантике на обеих платформах. Метаданные отделены от тел документов и траекторий. Работа с хранилищем, проверка импорта и сериализация выполняются в worker; UI получает компактные результаты.

Нормальный интервал записи движения — 2 секунды, максимум 256 отсчётов на chunk. Последний неподтверждённый интервал может потеряться при принудительном завершении процесса; UI сообщает о неподтверждённых данных и ошибке записи. Все подтверждённые транзакции должны переживать обычный перезапуск; физическое отключение питания не обещает абсолютной долговечности браузерного хранилища. `complete` означает коммит: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event); ограничения долговечности описаны в [Using IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB).

## D-09. Инженерные бюджеты

Бюджеты из [acceptance.md](acceptance.md) принимаются как цели реализации, а не уже достигнутые результаты. Устройства для замеров выбирает исполнитель из доступных; точная модель/GPU/WebView указывается в отчёте. Без физического Android мобильная приёмка остаётся невыполненной, но подготовка и реализация ядра продолжаются.

## D-10. Статус готовности

Готовность к реализации означает: есть входы/выходы, состояние ошибок, инварианты, порядок задач, тестовые оракулы и ограниченные технические проверки. Она не означает, что уже измерены FPS, выбрана финальная графическая оптимизация или обучена модель человека. Эти результаты получаются задачами реализации с явными критериями выхода.

Основной режим заполнения и время ожидания подтверждены пользователем. Их последующая смена не требует переделки ядра. Неопределённые параметры новых производственных модулей не блокируют контрольный каталог и общий интерфейс расширения.
