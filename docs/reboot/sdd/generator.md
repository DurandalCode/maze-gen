# Контракт генератора v1

Зависимости: [геометрия](geometry.md), [решения](decisions.md), [приёмка](acceptance.md). Статус: базовый контракт для реализации. Пользователь подтвердил use-site как основной режим и 3 варианта с ожиданием до 60 секунд. Остальные defaults — инженерные решения D-06. Генератор работает на ПК, отдельный worker, без DOM/Three.js и без поведенческого оптимизатора в первом выпуске.

## Запрос

`GenerationRequest` содержит requestId, schemaVersion, generatorVersion, geometryVersion, catalogSnapshots, site, physicalProfile, seed, placement, topology, terminals, allocation, constraints, requestedVariants и budgets.

| Поле | v1 |
|---|---|
| site | Простой внешний контур с отверстиями; габариты до 100×100 м; default 50×50 м |
| catalogSnapshots | Выбранные определения и веса выбора; default квадрат/прямоугольник с одинаковыми весами; круг/треугольник доступны в контрольном каталоге |
| placement | free / orthogonal; default free; направление базовой системы задаётся seed или пользователем |
| topology | tree / cyclic; default cyclic; для cyclic extraConnections целое ≥1, default 8 |
| terminals | auto / fixed; fixed — две позиции на границе site, допустимое отклонение 1 м; реальные проёмы должны быть внутри этого допуска |
| allocation | site / module-budget; site стремится использовать площадь, module-budget содержит maxModules и/или поштучные caps для определений |
| constraints | Пределы профиля и включённые проектные ограничения; никакого скрытого ослабления |
| requestedVariants | 1–8; рабочий default 3 |
| workBudget | До 8 попыток на вариант и 50 000 локальных placement-checks на вариант; фиксируется в manifest |
| watchdogMs | Рабочий default 60 000 на запрос; максимум UI 300 000; не входит в seed/hash результата |

Число циклов проверяется на физическом семантическом графе: E−V+C. В v1 все доступные пространства связны, C=1. Для tree требуется 0, для cyclic — ровно extraConnections. Геометрические пересечения и касания не добавляют связи неявно. Если требуемая топология физически не помещается, возвращается отказ/неполный поиск, а не дерево под названием cyclic.

Изолированный остров стен определяется по компонентам физического препятствия, не касающимся внешней границы, и отражается отдельной метрикой. Само наличие цикла не доказывает невозможность прохождения по стене. Vortex и требования к поведению «ловушек» — отдельные будущие расширения, без недействующих переключателей в UI.

## Распределение площади и материалов

Режим site: генератор продолжает рост до исчерпания допустимых локальных расширений или лимита работы/ресурсов. Рабочая цель покрытия — 65% доступной площадки, мягкая; показатель задаётся пользователем и явно отделён от обязательных геометрических ограничений. Покрытие = площадь объединения доступных полов за вычетом препятствий / площадь site без запретных зон. Сумма площадей модулей не заменяет эту метрику.

Карта ниже мягкой цели может быть физически допустимой, но выводится с меткой `target-not-met` и фактическим покрытием. Она не учитывается как вариант, выполнивший цель. Её можно отдельно выбрать осознанно. Переключение цели в hard constraint требует повторной генерации и допускает отказ. Полное заполнение площадки не обещается для произвольных контуров и форм.

Режим module-budget: counts/caps — верхние пределы, их нельзя превышать; необязательный minModules делает минимум явным hard constraint. По умолчанию генератор стремится использовать доступный бюджет, но непоместившиеся модули перечисляются. Цены и денежная смета в v1 отсутствуют: выводятся геометрические количества и длины конструкции.

Лимиты ресурсов v1: до 2000 экземпляров, 4000 соединений, 8000 проёмов, 1000 отдельных стен и 400 000 физических сегментов после аппроксимации; входной сериализованный контур ограничен 100 000 сегментов. Лимит производной геометрии увеличен с 100 000 по результату B-03: M-100 по контракту содержит четыре M-50, а полный каркас исходного M-50 даёт около 92,5 тыс. сегментов. Состав нагрузки, размеры и критерии скорости не уменьшены; это корректировка инженерного default до первого выпуска. Это проверяемые пределы формата/вычислений, не гарантия FPS для любой комбинации. Для типовой приёмки нагрузки меньше и заданы в acceptance.md. Превышение даёт RESOURCE_LIMIT с фактическим значением до выделения больших буферов.

## Начальные проектные ограничения

Физические ограничения обязательны по [D-05](decisions.md): площадка, пересечения, реальные просветы, пролёты, связность всех доступных регионов, корректные вход/выход. Выключить физическую проверку можно только оставаясь в черновике редактора, такой документ не выдаётся как готовая карта.

Пределы прямого хода 12 м и хода без выбора 20 м из прежних опытов — включённые начальные проектные ограничения. Отключение явно сохраняется в запросе. Определение: на семантическом графе сжимаются цепочки внутренних переходов без выбора; длина считается по проверенной физической траектории. Прямой участок — последовательность отрезков с изменением направления ≤1°; разветвление завершает forced-run. Циклическая цепочка без выхода считается отдельной ошибкой достижимости/forced-run и не зацикливает обход.

Обзор, доля видимых тупиков и площадь неиспользуемых зон возвращаются метриками. В v1 они не запускают тысячи симуляций внутри генерации. Дополнительные hard thresholds появляются только вместе с точным алгоритмом проверки и стоимостью.

## Алгоритм первого построения

1. **Подготовка.** Валидировать запрос, раскрыть определения, проверить bounds/resources и совместимость размеров проёмов. Зафиксировать нормализованный requestHash и каталог. Запрещены Date.now, Math.random и зависимость результата от очередности worker-ответов.
2. **Потоки вариантов.** Seed варианта получается детерминированно из seed + generatorVersion + variantIndex; попытки имеют свои индексы. IDs объектов строятся из этих индексов. Один и тот же вариант не зависит от requestedVariants.
3. **Корень.** Для auto выбрать модуль и допустимое положение возле границы site с проверенным внешним входом. Для fixed корень привязан к допустимой области заданного входа. Отсутствие корня после фиксированного числа проб — NO_ROOT_PLACEMENT, а не случайная замена контура.
4. **Рост дерева.** В очереди свободные допустимые области проёмов. Детерминированно выбрать frontier и определение модуля. Кандидат строится от проёма в мировых координатах; free выбирает углы непрерывно по seed, orthogonal ограничивает ориентации экземпляров кратными π/2 относительно базового направления. По 32 локальные позы на выбранный frontier; затем frontier закрывается для этой попытки. Пространственный индекс даёт соседей, точные проверки подтверждают геометрию. Каждый новый модуль подключается одним соединением.
5. **Выход.** Для auto выбирается достижимый допустимый внешний проём с максимальной длиной проверенного графового маршрута среди внешних кандидатов, tie-break по ID; это эвристика, не доказательство максимальной человеческой сложности. Для fixed рост учитывает направление выхода; вариант без проёма в установленном допуске отклоняется.
6. **Циклы.** Для cyclic перебираются локальные пары свободных проёмов по расстоянию и ID. Добавить требуемое число независимых соединений, повторяя физические проверки. Каждый принятый цикл подтверждается на семантическом графе. Недостаток пар отклоняет попытку.
7. **Полная проверка.** Скомпилировать весь мир, проверить все компоненты, путь вход→выход, проектные ограничения, требуемые циклы, caps и вычислить метрики. Локальные проверки роста не заменяют этот этап.
8. **Выдача.** Принять первый полностью проверенный результат данной попытки, отвечающий hard constraints. Если мягкая цель не достигнута, сохранить отдельный target-not-met кандидат и продолжить ограниченный поиск. Полный успех варианта — первый кандидат, выполнивший и целевые настройки. После исчерпания попыток вернуть лучший допустимый target-not-met с прозрачным основанием: покрытие, затем длина маршрута, затем hash.

Разнообразие проверяется по нормализованному хэшу геометрии/связей с исключением IDs, seed, названия и абсолютного переноса: одинаковые размещения с новыми IDs не считаются разными вариантами. Отсутствие дубликатов не обещает субъективную непохожесть; метрики и план позволяют сравнить варианты.

## Выполнение, воспроизводимость и ошибки

Progress: stage, variantIndex, attemptIndex, workDone/workLimit, elapsedMs; не чаще 5 сообщений/с. Процент показывается только для известного фиксированного этапа, не выдумывается для поиска. Каждый этап имеет измерение времени и счётчики проверок.

Watchdog останавливает запрос с `interrupted` и причиной timeout, а не меняет критерий успешного варианта. Уже завершённые варианты immutable и доступны. Для каждого результата сохраняются seed, versions, variant/attempt index, workCounters и нормативные параметры. Остановка посреди попытки не публикует её непроверенную геометрию как готовую карту. Продолжить — повторить незавершённый вариант с теми же входами и большим watchdog, детерминированная работа повторяется; скрытое изменение seed запрещено.

Cancel немедленно подтверждается UI; worker прерывается по точке yield или terminate/recreate в пределах PF-06. Открытый проект не заменяется до выбора результата. Старый requestId/revision не может применить результат к новой правке. Генерация не запускается в фоне во время прохождения без отдельного явного действия.

Результат запроса: `complete | exhausted | interrupted | invalid-request | failed`; варианты: `ready | target-not-met`. `exhausted` означает отсутствие нужного результата в данном бюджете, не доказанную математическую невозможность. Диагностики содержат code, counts, ограничение и понятное объяснение; исключение библиотеки — INTERNAL_ERROR с безопасными диагностическими данными, не «карта невозможна».

## Контрольные проверки

- GEN-01: один запрос, разные число вариантов/порядок повторных запусков → одинаковый hash варианта с тем же индексом и версиями.
- GEN-02: tree имеет C=1 и 0 циклов; cyclic имеет точно заданное число; все рёбра проходят физическую проверку.
- GEN-03: добавить triangle/circle через каталог → общий алгоритм размещает допустимый контрольный пример без switch по ID определения.
- GEN-04: слишком узкая site, закрытый fixed exit, недостаточный бюджет → ограниченное завершение с диагностикой и сохранённым текущим проектом.
- GEN-05: timeout/cancel во время роста и финальной проверки → нет позднего применения; завершённые варианты сохраняются, незавершённый не объявляется ready.
- GEN-06: target-not-met не считается полным выполнением; включение hard coverage приводит к exhausted вместо скрытого принятия.
- GEN-07: исходные лимиты 12/20 м считаются в физических метрах, длинный модуль и служебные navmesh-вершины не создают фиктивных развилок.

## Первый пользовательский экран

Поля сгруппированы: площадка/терминалы, каталог/бюджет, структура/расположение, ограничения, варианты/ожидание. Расширенные параметры скрыты за раскрываемой секцией с единицами и объяснением. Seed можно скопировать. Отдельные действия «Создать варианты», «Отменить», «Продолжить поиск», «Открыть в редакторе».

Сравнение показывает статус ограничений, покрытие, модули по типам, длины конструкции, маршрут-эталон с пометкой приближения, развилки и циклы. Предпросмотр одного варианта не загружает 3D всех остальных. Рейтинг сложности человека отсутствует, пока исследовательский этап не принят.
