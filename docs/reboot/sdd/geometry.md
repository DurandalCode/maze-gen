# Контракт документа, каталога и геометрии

Статус: базовый контракт для реализации; рабочие настройки — [decisions.md](decisions.md). Область: один этаж, мировая плоскость x/z, высота y, метры; углы документа — радианы. В UI углы отображаются в градусах.

## Сериализуемые сущности

| Сущность | Обязательные поля и смысл |
|---|---|
| Definition | id, version, contentHash, boundaryLoops, parameters, openingRegions, constructionProfile |
| BoundaryLoop | id, замкнутая последовательность сегментов, role: outer/hole |
| Segment | id; line(from,to) или arc(center,radius,startAngle,sweep); 0 < abs(sweep) ≤ 2π |
| Parameter | id, числовые min/max/default; конечное значение, без исполняемых формул |
| Instance | id, definitionHash, parameterValues, position{x,z}, rotationRad |
| Opening | id, instanceId, regionId, boundarySegmentId, uCenter в [0,1], widthM, role: ordinary/entrance/exit |
| Connection | id, openingA, openingB; физическое соединительное пространство выводится детерминированно |
| FreeWall | id, centerline line/arc, constructionProfileRef; опоры видны в документе/производной конструкции |
| Site | внешний замкнутый контур и внутренние запретные области; неограниченная сетка отсутствует |
| Document | schemaVersion, documentId, revision, site, definitions, instances, openings, connections, freeWalls, physicalProfile, environment |
| MapRevision | revisionHash, immutable Document, versions, validationSummary, optional generationManifest |

Топологический порядок сегментов значим; массивы независимых объектов канонизируются по ID. Для параметризации v1 используются перечисленные встроенные построители `rectangle(width,depth)`, `equilateralTriangle(side)`, `circle(radius)` и явный контур `explicitLoops`. Все строители дают одинаковый тип BoundaryLoop; геометрия/генератор не ветвятся по названию конкретного каталожного модуля. Новый тип на существующих примитивах может быть explicitLoops без нового построителя.

Строительные параметры v1: сечение досок/стоек, толщина панели, высота, максимальные пролёты, шаблон допустимых опор и индивидуальные исключения. Поле толщины берётся из физического профиля и используется одинаково в рендере и коллизиях; значение для ткани фиксируется задачей B-02 в новом физическом профиле по сохранённым требованиям, при необходимости со справкой из Git (`ccd19ff`). Обязательного запуска или восстановления старого приложения нет. Не переносить расхождение «отрисованная толщина ≠ физическая» из старой версии.

Все определения в карте — чистые данные. Никаких eval, кода шейдеров или URL для загрузки определений из импортируемого файла. Шейдеры и материалы выбираются из известных приложению профилей. Неизвестный примитив/профиль даёт `UNSUPPORTED_PRIMITIVE`/`UNSUPPORTED_PROFILE`.

## Численная модель и идентичность

- Сериализованные координаты и размеры нормализуются до 10⁻⁶ м, углы — до 10⁻⁹ рад, −0 становится 0; NaN/Infinity запрещены.
- Boolean/offset адаптер Clipper2 использует целочисленную сетку 10⁻⁷ м (до 5×10⁻⁸ м на координату), версию geometry-v3-clipper2 и проверку результата. Площадные инварианты сравниваются с операндами на той же сетке; metadata и исходные дуги не переписываются. Выходные нулевые рёбра/остатки удаляются только внутри заданных epsilon/area-epsilon; значимое вырождение и ошибка библиотеки остаются диагностикой. См. D-02 и отчёт B-03.
- Геометрическое epsilon 10⁻⁶ м; для сравнения площадей epsilon 10⁻⁸ м². Порог физической ширины проверяется консервативно: сомнительный пограничный случай не объявляется проходимым.
- Кривая аппроксимируется с максимальной стрелой дуги 0,005 м. Для радиуса r шаг θ ограничен условием r·(1−cos(θ/2)) ≤ 0,005. Концы проёмов включаются в разбиение независимо от обычного шага.
- Аппроксимация имеет собственную версию; при узких просветах геометрия препятствий расширяется на верхнюю оценку ошибки. Результат не зависит от FPS, масштаба камеры или GPU.
- revisionHash = SHA-256 канонического геометрического/визуального содержимого и версий; timestamps, project/document ID, счётчик команд revision, само поле hash, название, выделение и кеши не входят. Идентификаторы элементов и их связей входят; при одинаковом hash каноническое содержимое одинаково.
- layoutHash содержит только физический документ: контуры, определения/их версии, экземпляры, проёмы/связи, профиль конструкции. WorldHash дополнительно включает версию компиляции физической геометрии; navHash — worldHash, radius и версию навигации. Визуальная правка не инвалидирует navHash. conditionHash отдельно фиксирует крышу, прозрачность, окружение, скорость и знания участника. Изменение этих условий сохраняет физический layout, но меняет условие попытки.
- Определения immutable: изменение определения создаёт новый hash/версию. Экземпляры не обновляются автоматически. Устаревшая ревизия worker не применяется.

Для межплатформенной воспроизводимости PRNG, порядок обхода и tie-break по ID фиксированы. PRNG-v1: xoshiro128**, 4 unsigned 32-bit слова, seed UTF-8 NFC → SHA-256 → первые 16 bytes little-endian; нулевое состояние заменяется [1,0,0,0]. Выход uint32/2³². Seed варианта хешируется как канонический массив [seed,generatorVersion,variantIndex,attemptIndex], без неоднозначной конкатенации строк. Контрольные векторы PRNG фиксируются в G-01/GN-01. Нормализация не доказывает одинаковую тригонометрию на всех движках: кросс-платформенные hash-тесты обязательны; расхождение закрывается детерминированной численной реализацией до допуска генератора.

## Проёмы и соединения

1. OpeningRegion задаёт допустимые интервалы u на устойчивом сегменте границы, диапазон ширины, допустимый класс соединений. Несколько проёмов на одном сегменте допустимы без пересечения вырезов и стоек.

Для замкнутой полной дуги разрешён интервал через u=1/0 с явным wrap=true. Для незамкнутой дуги пересечение конца сегмента запрещено, пока определение не задаёт отдельную составную область проёма. Пограничные параметры не исправляются скрытым переносом на другую сторону.
2. На линии ширина откладывается вдоль сегмента. На дуге widthM означает ширину хорды выреза; угловая полуширина asin(width/(2r)). Проём обязан полностью попадать в допустимую область. Его концы — точные точки исходного контура, ось — хорда, внешняя нормаль определяется ориентацией границы.
3. Стойки размещаются по краям выреза с реальными размерами. Номинальная ширина не заменяет проверку оставшегося просвета. Пол и подход должны оставаться связными после учёта опор.
4. Connection соединяет пары концов двух проёмов простым четырёхугольником без самопересечения; ориентация концов нормализована по внешним нормалям. Обе нормали должны смотреть в соединение. Равенство номинальных ширин не обязательно, но минимум просвета обязателен по всему пути.
5. Длина каждой боковой стены ≤3 м по physical-v1. Геометрия соединения не пересекает третьи модули, другие соединения, стены и запретные зоны. Общая граница с владельцами проёмов разрешена только в соответствующих вырезах.
6. Проём участвует максимум в одном соединении. Entrance/exit — разные внешние проёмы, по одному каждого типа в первом выпуске; они соединены с виртуальным внешним стартом/финишем. Прочие внешние открытые выходы запрещены в проверенной карте.
7. Касание модулей само по себе не создаёт переход. Для соприкасающихся согласованных проёмов допускается direct-join с нулевой длиной соединения и явным ребром. Вырожденные четырёхугольники не передаются в boolean-ядро.

Лимит входа — 100 000 сериализованных сегментов, лимит производного мира — 400 000 физических сегментов (контуры полов/соединений и footprints конструктивных элементов). Увеличение исходного инженерного лимита производной геометрии документировано в generator.md по результатам B-03; лимиты экземпляров/соединений и приёмка производительности не изменены.

## Подготовка физического мира

`compileGeometry(document, versions) -> PhysicalSnapshot | GeometryDiagnostics` выполняется без UI. Выход содержит worldHash, поверхности полов/крыши с отверстиями, панели, опоры и каркас с IDs, spatialIndex, openPassages, accessibleRegions, bounds и объёмы для материалов. Рендерер не придумывает отдельные стены/стойки; материалы считаются по тем же элементам.

Порядок: проверить схему и пределы → раскрыть определения → трансформировать контуры → вырезать проёмы → построить конструкцию → построить соединения → проверить пересечения/пролёты → подготовить проходимую область. Отрицательный результат содержит code, objectIds, location и фактическое/допустимое значение.

Для кривых исходный контур сохраняется в документе, а физическая сегментация — часть результата compileGeometry. 2D и 3D могут дополнительно сглаживать отображение только внутри допуска; опоры, вырезы, доступная площадь и ширина прохода остаются из одного снимка.

Круглый тестовый профиль реализуется явными прямыми секциями; опоры возникают по правилам профиля и отображаются/учитываются в смете. Они не возникают из случайных треугольников крыши. Пролёты и дополнительные опоры проверяются после вырезания проёмов. Каталог обязан иметь допустимую конфигурацию хотя бы двух проёмов на круге и треугольнике.

Пересечение внутренних площадей модулей запрещено; общий край допускается только при согласованной физической границе без двойных стен. Здания/отверстия внутри site не превращаются в проходы. Все пространства, объявленные доступными, должны принадлежать компоненте entrance; изолированные острова препятствий разрешены, недостижимые комнаты — ошибка.

## Навигация и движение

`buildNavigation(PhysicalSnapshot, radius) -> NavigationSnapshot` строит область допустимых центров игрока. Препятствия расширяются на радиус и погрешность, граница пола сужается; для polygon-контуров расширение задаётся объединением исходного полигона, полос вдоль рёбер и консервативных дисков у вершин. boolean-адаптер получает уже валидные полигоны. Результат с отверстиями триангулируется, соседство строится по общим рёбрам с положительным просветом. Только касание вершинами не даёт ребра.

Путь строится A* по navmesh, затем funnel и окончательная проверка swept disk по PhysicalSnapshot. Веса — метры; результат маркируется `reference-approximate`, пока глобальная оптимальность не доказана. Если локальная траектория не проходит проверку, снимок недопустим, а не исправляется движком телепортацией.

Семантический граф пространств/проёмов строится отдельно от треугольников navmesh. Вспомогательные вершины не увеличивают cycles/decisionCount. Стены внутри модуля могут разделить пространство: его нельзя представлять одной точкой по центру. Компоненты, реальные области выбора и связи определяются физически.

`move(position, displacement, radius)` делает непрерывную проверку перемещения с пространственным индексом; контакт разрешает скольжение по касательной. Нельзя перескакивать препятствие на длинном кадре. Общие сегменты маршрутов проверяются тем же предикатом. Физика фиксированным шагом 1/60 с, максимум 5 шагов за render frame; длинная пауза не догоняется движением. Скорость ходьбы 1,4 м/с, бега 2,8 м/с — существующие значения.

## Инвалидация

| Изменение | Пересчитать |
|---|---|
| Выделение, панорамирование, название | Только UI / метаданные |
| Цвет, солнце, лес, прозрачность | Визуальное состояние, conditionHash и наблюдения при необходимости; не navmesh |
| Крыша | Визуальные поверхности, условия наблюдения; одноэтажная проходимость сохраняется |
| Положение/параметры модуля, стена, проём, физический профиль | Затронутые физические области, индекс; затем навигация/валидация и зависимые метрики |
| Новая версия алгоритма | Соответствующий кеш/анализ; исходный документ immutable |

Во время drag разрешён только локальный предпросмотр, полная валидация после commit в worker. Одновременно хранить не более текущего и одного готовящегося полного snapshot; история хранит команды/патчи. Результат local-valid не равен global-ready.

## Геометрические оракулы

GEO-01: rectangle 2×2 и triangle(side=4) имеют аналитическую площадь, circle(r=2) — площадь в пределах допуска аппроксимации.

GEO-02: две комнаты с соединением и повернутыми проёмами дают физически проходимый путь; сужение до 0,99 м возвращает WIDTH, даже если центры графа связаны.

GEO-03: отверстие пола не покрыто крышей/полом, участок маршрута через него отклоняется; касание углов не создаёт проход.

GEO-04: асимметричный/вогнутый explicitLoops с центроидом вне доступной области имеет допустимые внутренние опоры маршрута; разделяющая стена обнаруживает недостижимую часть.

GEO-05: JSON round-trip смешанной карты сохраняет worldHash, проёмы, площадь и допустимые маршруты; обновление внешнего каталога ничего не меняет.

GEO-06: при rotation ±π и проёме через начало/конец дуги нет разрыва; дуга почти нулевой длины, самопересечение, несовпадающий стык и превышение лимита сегментов отклоняются.
