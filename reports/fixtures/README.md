# B-03 — независимые контрольные карты

Статус: выполнено. Входы создаются `tests/fixtures/factory.ts`, независимо от генератора. Канонические документы, hashes, состав, physical segment count, маршрут/его hash и версии зафиксированы рядом в `*.document.json` и `results.json`.

Команда: `bun scripts/verify-fixtures.ts`. Можно передать точные ID для ограниченного прогона. Каждый случай выполняется в отдельном worker с лимитом 60 с; timeout — не pass. Отчёт фиксирует sourceHash, неизменность источников во время прогона, runtime/CPU/RAM/OS. Тайминги этого функционального прогона не заменяют PERF-gates.

- F-01: две комнаты и повёрнутое соединение.
- F-02: 2×6, circle, triangle; общий compile/nav без switch по ID формы.
- F-03: отверстие пола, отдельный остров стены, L-контур с вершинным центроидом вне пола; касание углами отклоняется как UNREACHABLE.
- F-04: физический просвет 0,99/1,00/1,01 м и круглый wrap-проём. 0,99 отклоняется WIDTH, а не считается ready.
- F-05: известные деревья, одно и два кольца; количество циклов проверяется независимо от triangulation.
- M-50: 50×50 м, исходный состав сохранён — 240 квадратов, 40 прямоугольников, 20 треугольников, 20 кругов. Всего 320 модулей; 319 явных соединений, дерево. Конструкция целиком внутри site, включая толщину и доски. Положение всех модулей по x сдвинуто на 0,1 м до фиксации baseline, чтобы край кругов не выносил каркас за площадку.
- M-100: четыре перенесённых M-50 с тремя явными соединениями через швы; один вход/выход. 1280 модулей; 1279 соединений, дерево. При добавлении швов прежние ненужные внешние проёмы закрыты; исходный состав четырёх частей сохранён.

Сохранены все физические элементы. Измеренный полный каркас M-50 — 92 508 сегментов, M-100 — 370 286. Лимит производной геометрии до первого выпуска скорректирован до 400 000 (generator.md / D-02), входной лимит остался 100 000. Это явное изменение инженерного default по измерению; уменьшения состава карты или ослабления FPS/latency criteria нет.

При проверке большого набора первоначальный polygon-clipping дал воспроизводимый сбой SweepLine. По правилу G-03 заменён только boolean/offset адаптер на clipper2-ts 2.0.1-19; публичный документ и аналитические оракулы сохранены. Используются сетка 10⁻⁷ м, round-offset с консервативной прибавкой допуска дуги и пространственное разбиение. Все исходные оракулы повторены после замены. Ссылка на первичный API: https://github.com/countertype/clipper2-ts.

Benchmark-маршруты — зафиксированные физически проверенные reference-approximate пути. Их нельзя подменять более лёгким маршрутом при оптимизации. Площадь/состав и ограничения не меняются скрыто. VIS-01 и PERF пока отдельно не приняты; поле status=pass здесь означает правильный исход функционального fixture, включая ожидаемые отказы двух отрицательных случаев.
